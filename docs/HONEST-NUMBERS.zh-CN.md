# 诚实数字

穴居有时省 token。穴居有时费 token。此页说明哪种情况是哪种，全部真实数字。无营销。若穴居对你的工作流是亏的，此页告诉关掉它。

## 穴居实际做什么

穴居是一项系统提示技能。它让模型**写更短输出**。全部机制即此。它不压缩你的输入、上下文、文件或模型思考 token。

## 测量数据

| 项目 | 数值 | 测量方式 | 来源 |
|---|---|---|---|
| 对比默认冗长回复的输出减少 | **平均65%**（范围 22–87%） | 真实 Claude API token 计数，10 个提示词 | [`benchmarks/`](../benchmarks/) |
| 技能带来的输入减少 | **0%** | 它是输出风格指令 | — |
| 技能*增加的*输入成本 | **每轮约 1–1.5k token** | SKILL.md 规则（约 5 KB）注入上下文，加技能列表条目 | [`skills/caveman/SKILL.md`](../skills/caveman/SKILL.md) |
| `/caveman-compress` 压缩记忆文件 | 约 46% 平均输入减少，每会话，仅限这些文件 | 真实文件，token 计数在 README 表中 | [README](../README.md#benchmarks) |

这些数字仅输出 token——技能不压缩输入、上下文、文件或模型思考 token。完整评估工具链及修正历史记录于 [`evals/README.md`](../evals/README.md)（英文）。

## 穴居何时赚

- **长篇健谈输出。** 解释、架构讨论、代码审查、文档、调试步骤——任何模型单次回复超过 1k+ 输出 token 的场景。50–87% 的削减发生在这里。
- **verbose agent 的长会话。** 每次回复的节省累积；固定的约 1–1.5k/轮规则成本不变。
- **阅读速度。** 更短回复更快结束，你读得更快。对很多用户，这而非成本是真正的收益。

## 穴居何时亏（净负）

实事求是：**技能每轮约费 1–1.5k 输入 token。若节省的输出少于这个数，你在花钱用它。**

- **简洁编码问答**（[#145](https://github.com/JuliusBrussee/caveman/issues/145)）。若你正常回复约 150 输出 token，穴居省大概 70–100 个，但每轮花约 1k+ 输入开销。净亏。#145 的用户恰好测量了这一点。他们是对的。
- **按请求或信用额而非 token 计费的代理**（[#506](https://github.com/JuliusBrussee/caveman/issues/506)）。GitHub Copilot 按 premium *请求*收费。更短答案算同一次请求。穴居不能降低你的 Copilot 信用额消耗。同样逻辑适用所有按消息定价的。
- **会话级别总计**总是比输出减少标题小，因为在 agentic coding 中输入 token（你的提示词、上下文、文件、注入规则）远超输出 token。独立会话级测量在输出密集型工作负载上大约**14–21% 总节省**——在简洁工作负载上低于零。
- **某些工具端计数器往反方向走**（[#550](https://github.com/JuliusBrussee/caveman/issues/550)）。一次 Cursor A/B 显示带穴居 430 万 token vs 不带 100 万，以及两倍实际时间。我们无法精确复现那次运行，但诚实的解读是：规则重注入、重试和缓存/上下文计费在某些代理中可能淹没输出节省。若你的 A/B 看起来那样，穴居对你净负。关掉它。希望石头管用不能使石头管用。

## 自己测量

1. **`/caveman-stats`**（Claude Code）读取你的真实会话日志并打印实际输入/输出 token 数。"已省"行是**估算**：用基准比例外推没有穴居时的输出量。真实用量，估算基线——输出标为 `est.` 正是此原因。
2. **唯一完全诚实的测试是 A/B**：同样任务带/不带穴居各跑一次，对比你的供应商自身用量/账单页面的数字。那个数字胜过本仓库打印的任何东西。
3. **复现我们的数字**：`benchmarks/run.py`（需要 Anthropic 密钥）和 `evals/measure.py`（离线，读取已提交快照）。

## 经验法则

> 正常回复长于约 1.5–2k 输出 token → 穴居大概给你省钱。
> 正常回复短于此，或你按请求付费 → 穴居大概让你花钱。
> 无论如何，穴居回复读起来更快。那部分是免费的。

发现某个工作负载上我们数字不对？[提交 issue](https://github.com/JuliusBrussee/caveman/issues) 附带 A/B。我们将其放在此页。
