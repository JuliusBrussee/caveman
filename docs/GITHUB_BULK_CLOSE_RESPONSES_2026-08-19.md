### Issue #522

**Summary:** Six architecture and support questions; answer directly, then close as answered.

> Thanks for the thoughtful questions. Short answers:
>
> 1. SKILL.md uses explicit compression rules plus Auto-Clarity exceptions; it reduces risk but cannot guarantee zero semantic loss, so tests and task evaluation still matter.
> 2. Host-specific lifecycle hooks and plugins inject active rules and maintain a mode flag. Examples support the rubric, but mode control is not fine-tuned model behavior.
> 3. Installers register host-specific hooks in each client’s supported configuration surface. /caveman-stats reads local transcript and state data on demand; it is not a blocking live-output interceptor.
> 4. /caveman-compress protects code fences, inline code, URLs, paths, and identifier-like spans, then validates output and keeps recovery paths. “Perfect byte preservation” is not promised for arbitrary prose files, which is why consent, backups, and review remain required.
> 5. Cavecrew uses explicit routing rules: investigator for locating code, builder for obvious one- or two-file edits, reviewer for focused diff review. It is guidance, not a learned complexity classifier.
