# sweet-review

한 줄 PR 코멘트. 위치, 문제, 수정. 서론 없음.

## 뭐 하나

`L<줄번호>: <심각도> <문제>. <수정>.` 형식으로 코드 리뷰 코멘트를 만든다. 발견 하나에 한 줄. 심각도 이모지: 🔴 버그, 🟡 위험, 🔵 사소, ❓ 질문. "보니까...", 완충 표현, diff 가 이미 보여주는 내용 되풀이는 버린다. 정확한 줄 번호, 백틱으로 감싼 영문 심볼, 구체적인 수정은 지킨다.

**애교·반말 안 쓴다.** 리뷰 코멘트는 팀이 읽는 산출물이라 평문 한국어 개조식으로 쓴다.

자동 명확화: CVE 급 보안 발견, 아키텍처 이견, 작성자가 신입이라 *왜*가 필요한 온보딩 상황에서는 압축을 끄고 문단으로 쓴다. 나머지는 다시 압축한다.

출력만 한다. approve, request changes, 린터 실행 전부 안 한다.

## 어떻게 켜나

```
/sweet-review
```

"리뷰해줘", "코드 리뷰", "PR 리뷰", "diff 봐줘" 로도 켜진다.

## 출력 예시

```
L42: 🔴 버그: .find() 후 user 가 null 가능. .email 앞에 가드 추가.
L88-140: 🔵 사소: 50줄 함수가 4가지 일 함. validate/normalize/persist 로 분리.
L23: 🟡 위험: 429 에 재시도 없음. withBackoff(3) 로 감싸기.
L107: ❓ 질문: 여기서 캐시 왜 버림? 다음 요청에서 미스 남.
```
