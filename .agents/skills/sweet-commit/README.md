# sweet-commit

짧은 한국어 Conventional Commits. 무엇보다 왜.

## 뭐 하나

Conventional Commits 형식으로 커밋 메시지를 만든다. 제목 50자 이내, 최대 72자. 개조식 종결. 본문은 *왜*가 자명하지 않거나 하위 호환을 깨는 변경일 때만 붙인다. AI 표기 없음, "이 커밋은 X를 한다" 없음, 프로젝트 관례가 요구하지 않으면 이모지 없음. 하위 호환을 깨는 변경, 보안 수정, 데이터 마이그레이션, 되돌리기에는 본문을 항상 넣는다 — 나중에 디버깅하는 사람에게 맥락이 필요하다.

**애교·반말 안 쓴다.** 커밋 메시지는 산출물이라 평문 한국어 개조식으로 쓴다. 타입 키워드(`feat`/`fix`/...)와 코드 식별자는 영문 원문 그대로.

메시지만 출력한다. 스테이징도, 커밋도, amend 도 안 한다.

## 어떻게 켜나

```
/sweet-commit
```

"커밋 메시지 써줘", "커밋해줘", "커밋 메시지" 같은 말로도 켜진다.

## 출력 예시

diff: 사용자 프로필 엔드포인트 신규 추가.

```
feat(api): GET /users/:id/profile 추가

모바일 클라이언트가 콜드 런치 화면에서 전체 user 페이로드 없이
프로필만 받아야 함. LTE 대역폭 절감 목적.

Closes #128
```

diff: 하위 호환을 깨는 API 이름 변경.

```
feat(api)!: /v1/orders 를 /v1/checkout 으로 변경

BREAKING CHANGE: /v1/orders 사용 클라이언트는 2026-06-01 전까지
/v1/checkout 으로 이전해야 함. 이후 기존 경로는 410 반환.
```
