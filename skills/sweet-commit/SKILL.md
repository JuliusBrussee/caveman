커밋 메시지를 짧고 정확하게 쓴다. Conventional Commits 형식. 군더더기 없음. 무엇보다 왜.

**말투 예외.** 이 스킬은 애교·반말을 쓰지 않는다. 커밋 메시지는 산출물이라 평문 한국어 개조식으로 쓴다. 스윗 본체의 "코드·커밋·PR은 평문" 경계를 그대로 따른다.

## 규칙

**제목 줄:**
- `<type>(<scope>): <한국어 요약>` — `<scope>` 는 선택
- 타입: `feat`, `fix`, `refactor`, `perf`, `docs`, `test`, `chore`, `build`, `ci`, `style`, `revert` — 영어 원문 그대로
- 개조식 종결: "추가", "수정", "제거" — "추가했음", "추가합니다" 아님
- 50자 이내 권장, 최대 72자 (한글은 글자당 바이트가 크니 더 짧게)
- 끝에 마침표 없음
- 콜론 뒤 표기 관례는 프로젝트 기존 커밋에 맞춘다

**본문 (필요할 때만):**
- 제목만으로 자명하면 아예 생략
- 본문을 쓰는 경우: 자명하지 않은 *왜*, 하위 호환을 깨는 변경, 마이그레이션 주의사항, 연결된 이슈
- 72자에서 줄바꿈
- 불릿은 `-`, `*` 아님
- 이슈·PR 참조는 맨 끝: `Closes #42`, `Refs #17`

**절대 안 들어가는 것:**
- "이 커밋은 X를 한다", "나는", "우리는", "이제", "현재" — 무엇을 했는지는 diff가 말한다
- "요청에 따라..." — Co-authored-by 트레일러를 쓴다
- "Generated with Claude Code" 등 AI 표기 — 사용자 자체 규칙이 `Assisted-by`/AI 표기 트레일러를 요구할 때만 트레일러로 추가
- 이모지 (프로젝트 관례가 요구하면 예외)
- scope 에 이미 있는 파일명 반복

## 예시

diff: 사용자 프로필 엔드포인트 신규 추가, 왜를 설명할 본문 필요
- ❌ "feat: 데이터베이스에서 사용자 프로필 정보를 가져오는 새로운 엔드포인트를 추가했습니다"
- ✅
  ```
  feat(api): GET /users/:id/profile 추가

  모바일 클라이언트가 콜드 런치 화면에서 전체 user 페이로드 없이
  프로필만 받아야 함. LTE 대역폭 절감 목적.

  Closes #128
  ```

diff: 하위 호환을 깨는 API 변경
- ✅
  ```
  feat(api)!: /v1/orders 를 /v1/checkout 으로 변경

  BREAKING CHANGE: /v1/orders 사용 클라이언트는 2026-06-01 전까지
  /v1/checkout 으로 이전해야 함. 이후 기존 경로는 410 반환.
  ```

## 자동 명확화

다음은 항상 본문을 넣는다: 하위 호환을 깨는 변경, 보안 수정, 데이터 마이그레이션, 이전 커밋을 되돌리는 변경. 제목 한 줄로 압축하지 않는다 — 나중에 디버깅하는 사람에게 맥락이 필요하다.

## 경계

커밋 메시지만 만든다. `git commit` 실행 안 함, 스테이징 안 함, amend 안 함. 붙여 쓸 수 있게 코드 블록으로 출력한다. "스윗 커밋 끄기" / "normal mode" 하면 원래의 긴 커밋 스타일로 돌아간다.
